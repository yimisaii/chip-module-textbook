# 教材与工程返工问题卡

每次新增问题时，记录可观察的症状、触发条件、可查的原因、具体修复及回归证据。把仅在特定器件、SDK 或排版引擎出现的问题保留在相应范围内。下表路径相对于原工作区。

## 内容与排版

| --- | --- | --- |

| 源码摘录带入下一个函数的注释，长清单断在函数开头 | 使用源码标记限制摘录边界，按完整逻辑段续页，标示续页 | 比较清单与 C 源、查看分页。`STM32U5_DMA模块教材/验证记录.md`、`STM32U5_第三章教材/05_编写与验证工具/验证记录.md` |

## 工程与实验

| 症状或误判 | 本次方法 | 回归检查与既有证据 |
| --- | --- | --- |
| 两个 `main`、重复启动文件或错误的 IRQ 向量 | 每个目标只编入一个应用入口、一个启动文件、一个 `SystemInit` 和一组有效中断处理程序。对照启动向量检查实际符号 | 静态核对后，按各目标真实构建并查链接映射。`STM32U5_第三章教材/02_代码/README.md` |
| 看见 DMA `length` 就把元素个数原样传给另一层 API | 分开记录应用元素数、单元素宽度、缓冲区字节数、具体 API 参数单位与硬件寄存器语义。保持数组退化前的容量信息 | 通过已知模式逐项比对数据，测试边界大小。`STM32U5_DMA模块教材/02_代码/README.md`、`STM32U5_第六七章教材/04_资料与对应表/官方资料核对记录.md` |
| DMA 超时后马上重用目标缓冲区 | 检查终止调用和通道是否实际停止。硬件状态未确认时，保留缓冲区，走错误处理 | 注入超时，观察停止状态、报告字段及重试条件。`STM32U5_DMA模块教材/02_代码/README.md` |
| 链表节点地址不满足窗口约束，或把单节点完成当成整链完成 | 从具体 GPDMA 型号和模式核对节点对齐、链接寻址和完成事件粒度。用链接脚本放置节点，运行前核对地址 | 查 map、检查节点地址，完成后分别验证两段数据。`STM32U5_DMA模块教材/验证记录.md` |
| 预装载首次读到旧值，重启清除了真实故障锁存 | 区分影子与活动寄存器，按器件规定初始化并确认生效点。把正常停止、故障锁存和受控恢复分开 | 针对首次有效周期、重启时故障仍在、主动恢复三个情形做回归。`ai/chapter3/docs/实施记录.md` |
| 将模式名称等同于硬件语义 | 用时序和有效输出表达差异。既有 PWM 案例中，门控可能暂停计数且维持当前输出状态。互补、刹车和恢复条件分别核对 | 画清包络无效区和预期电平，按实际硬件测量。`STM32U5_第三章教材/02_代码/README.md` |
| ESP-IDF v5.3.4 编译本例时，`ledc.h` 报找不到 `driver/gpio.h` | 应用组件显式声明 `esp_driver_ledc` 和 `esp_driver_gpio` 两项依赖；按固定 SDK 的组件接口确定依赖 | 重新执行 ESP32-C3 目标编译与链接，核对 ELF 架构和 map。见 [LEDC 验证记录](../examples/esp32c3-ledc/VERIFICATION.md) |
| 见到 GCC 语法检查成功就填“Keil 已构建”，或把算法波形写成实测 | 按资料推导、主机检查、目标构建、硬件实测分别登记。测试证据保留工具及其覆盖范围 | 查找真实目标工具链日志或上板记录，缺少相应证据就标记未执行。`STM32U5_DMA模块教材/验证记录.md`、`CCS_Chapter3/firmware/build/f28335/build_report.json` |
