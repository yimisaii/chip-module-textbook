# 外设教材的写作与验收

适用于从已有教材中抽取章法，再为目标器件重写一章原理和实验。已有教材用于校准教学顺序、解释深度、图表密度和练习类型。建立章节映射表，逐项注明保留的教学目的、目标器件如何实现、哪些原有功能没有直接对应。跨平台实例要重新核对寄存器、事件、资源数量、时钟和引脚。

## 从读者要验证的现象开始

1. 定义学习目标、读者基础、完整料号或开发板、工具链和实验前提。选择一个读者可以明确观察的结果，例如源数组与目标数组完全相同。
2. 写清模块在系统中的位置、信号及数据的方向。沿一次真实操作讲时钟、输入、状态转移、输出及错误路径，再引入配置所需的寄存器、字段和 HAL 参数。
3. 用一组具体值走完整的换算。先列已知量、量纲、边界和取整，再解释寄存器值、API 参数或缓冲区空间如何得到。给出公式适用的模式和时钟条件。
4. 组织最小实验、进阶应用与故障复现。每个实验列配置前提、工程入口、源文件与函数、调试步骤、成功和失败的观察量。用一条调用链串起入口、配置、启动、完成和恢复。
5. 用章末练习验证理解。包含一个算例、一次边界参数变更或一个故障诊断，另附答案要点和复核方法。已有章节体例优先，页数以实际内容和分页决定。

## 先设计程序，再写程序清单

- 把纯计算、外设配置、板级入口分开。外设状态用状态表或时序图说明，列启动顺序、事件来源、标志位清除和退出条件。
- 按真实调用链选择关键代码。通常包括一个初始化/配置函数、一个可观察的主流程、一个中断或异步完成路径以及一个失败处理路径。跨函数片段给出文件名和阅读顺序。
- 源文件是唯一代码来源。用符号或显式摘录标记定位程序清单，生成后比较实际内容并检查块的起止边界。中文注释解释单位、动作顺序、资源归属、返回值与不可省略的约束。
- 将实验复现与硬件测量分别留证。对共享状态明确谁读、谁写、何时交接。对超时说明时基、检测点、停止的证据和何时允许重试。

## 插图、图标与表格

| 要解释的问题 | 适合的呈现 | 出图前检查 |
| --- | --- | --- |
| 硬件在系统中怎样连接 | 模块框图或接线图 | 箭头指向、时钟域、端口、供电与地 |
| 位和字段怎样影响配置 | 位域图配关键位表 | 位号、访问语义、复位值、保留位及适用模式 |
| 信号或缓冲区何时变化 | 时序图、状态图或归属图 | 时间方向、沿、采样点、单位、产生者和消费者 |
| 算式与实现是否一致 | 同源数据曲线与参数表 | 坐标单位、采样条件、数值来源和数据版本 |

技术图优先保存可编辑 SVG。Word 中可嵌入由该 SVG 生成、在目标字号下清晰的 PNG。稳定素材 ID 与章内编号独立，图号按首次引用顺序生成。图例区分原理示意、理论或仿真数据、硬件实测。文件清单记录图号、素材、输入数据、适用器件和来源定位。表格从同一份源数据输出为 Word 原生表格和所需的 CSV，公式保留可编辑结构。

如需提示图标，先建立小型语义表，再统一轮廓、线宽、留白与最小尺寸。例如用不同图形表示实验步骤、调试观察和故障提示，旁边保留文字标签。缩小到实际印刷尺寸检查，黑白打印时同样能区分。电气符号使用目标领域的符号约定。

既有 STM32U5 成品采用教材书页、黑白图、图题下置和表题上置。相同版式的续章可以沿用字号、段落、页码与标题层级。其他交付以本次规定的样式为准。

## 交付复核

1. 源码和工程复核。检查编译宏、目录依赖、启动文件、链接区、目标入口、关键边界用例与错误路径。由当前环境实际执行的检查决定证据级别。
2. 稿件结构复核。核对引用、图表及公式编号、代码摘录、符号、单位、实测/推导标签与附件。对每个应用节核对是否有对应代码、观察量或明确的适用边界。
3. 渲染复核。用目标排版引擎生成 PDF，再检查全部页图中的裁切、表头、代码续页、页码、曲线标注和公式。Word 与替代引擎的分页可能不同。修改内容后重新渲染，若使用页图摘要定位变动，同时核查受牵连的相邻页及全文编号。
4. 交付清单。记录交付版本、构建或导出方法、证据及其覆盖目标。按需提供源稿、工程、插图数据和习题答案。缓存、临时渲染和第三方材料按交付范围分开管理。
